# Controller

従来型 ESP32 のジョイスティック校正と、RadioLib による nRF24 2台への送信。
現在の PlatformIO ボード設定は Freenove ESP32-WROVER。

## 配線

- スティック: LX=GPIO32、LY=33、RX=34、RY=35。電源は3.3V、GND共通。
- nRF24: SCK=18、MISO=19、MOSI=23、CSN=5、CE=4、IRQ=27。電源は3.3V。
- カメラは使用しない（GPIOの競合を避ける）。

## OLED表示（秋月112031）

128×64 I2C OLED。現行SSD1315／旧SSD1306向けにAdafruit SSD1306ライブラリを使用。
実機表示は未確認。

| OLED端子 | ESP32 |
| --- | --- |
| GND | GND |
| VDD / VCC | 3V3 |
| SCK / SCL | GPIO22 |
| SDA | GPIO21 |

端子は実物の印字で照合する。SCKはこの製品ではI2Cクロックで、nRF24のSPI SCKとは別。
7ビットI2Cアドレスは0x3C。起動時に応答を確認し、未接続時もシリアルで操作できる。
表示更新は約200ms周期。画面が小さいため英数字を使う。

- 校正画面: NOW=現在値、MIN/MAX=取得中の最小/最大。NVS:YES=保存済み設定あり、C:OK=中央取得済み。
- `c`実行時に全軸の保存条件を満たすと `READY: s to save`。
- 保存失敗は `NVS SAVE FAILED`、無線初期化失敗は `nRF INIT ERR` とコードを表示。
- コントロール画面: A/Bそれぞれの返信結果（RX OK / RX BAD / NO REPLY）、連番、返信された4軸値。返信がない場合は値を ---- 表示。
- RX OKは受信側が値を検証して返信し、Controllerが連番・送信値との一致を確認した結果。TX:0だけでは返信成功を意味しない。
- 校正中は無線送信を行わない。校正操作のc/s/g/rは引き続きシリアルから入力する。

製品情報: https://akizukidenshi.com/catalog/g/g112031/

## 操作（シリアル115200 baud）

1. 起動すると校正画面。2本のスティックを上下左右の端まで動かす。
2. 中央に戻して手を離し、`c`を送信。約0.3秒の平均で中央を取得する。
3. `s`を送信。最小・最大・中央をNVSに保存し、読み戻しを確認してコントロールモードへ移る。
4. コントロールモードの`r`で送信を止め、再校正する。

- 再起動後も校正画面から開始。`g`で保存済みの校正値を使用して送信開始。
- 校正画面の`r`は今回の測定をリセットする。保存済みデータは新たに`s`が成功するまで保持。
- `h`で操作案内を再表示。
- 保存条件: 全軸の最大−最小が500以上、中央から両端までそれぞれ100以上、`c`実行済み。
  これは不十分な測定を防ぐ目安であり、配線の正常性を保証するものではない。
- 無線初期化に失敗しても保存データは保持。配線修正後に`g`で再試行。
- 校正値を基に各軸を−1000〜1000へ変換する。中央は0。デッドゾーン・軸反転は未設定。

## 受信側が合わせる設定

- RadioLib `begin(2400, 1000, -12, 5)`。周波数2400MHz、速度1000kbps、アドレス長5バイト。
- A: `12 34 56 78 90`、B: `B2 34 56 78 90`（16進数）。受信pipe 0に自機のアドレスを設定。
- 同じ14バイトをA、Bの順に送信し、各送信直後に最大40ms返信を待つ。目標周期50ms。ACK待ち・返信待ち・再送で遅くなる場合がある。

| オフセット | 長さ | 内容 |
| --- | --- | --- |
| 0 | 1 | ASCII `J` (0x4A) |
| 1 | 1 | 形式バージョン1 |
| 2 | 4 | uint32連番、リトルエンディアン |
| 6 | 2 | int16 LX、リトルエンディアン |
| 8 | 2 | int16 LY、リトルエンディアン |
| 10 | 2 | int16 RX、リトルエンディアン |
| 12 | 2 | int16 RY、リトルエンディアン |

受信側はバイナリとして読み、長さ・識別子・バージョンを確認する。
文字列用の受信表示だけでは正しく表示できない。
受信側プロジェクトは隣の `../ControllerReceiver`。A/B用のビルド環境を用意。
有効な受信が1秒以上途絶えると、受信側シリアルにRX TIMEOUTを表示する。

## アプリケーション返信

返信先は `C3 34 56 78 90`、16バイト。元の14バイトの先頭を `R` に変更し、
オフセット14に受信機ID（ASCII A/B）、15に結果（0=正常、1=軸範囲外）を追加する。
連番・4軸値は受信したバイト列をそのまま返す。長さ・識別子・版が不正な要求は返信しない。
ControllerはID・連番・4軸値・結果を確認し、現在の要求に対応する返信のみ表示する。
A/Bの片方だけでも動作するが、未接続側はNO REPLYとなり待ち時間が増える。

## 入力の移動平均
送信する4軸は5ms周期のADC専用タスクで直近8サンプルを平均する（窓は約40ms、定常時の平均遅延は約17.5ms）。通信のACK待ち中もサンプリングを継続。起動時は取得済みサンプル数で割り、ゼロ埋めによる偏りを防ぐ。校正の端点は生値、中心は従来どおり64回平均で取得する。設定はsrc/main.cppのaverageSamplesとsamplePeriodMs。
